 # SpeedyCRM — Архитектурная Multi-Bot SaaS Платформа 🥊🚀

Высокопроизводительная CRM-система для автоматизации спортивных клубов, студий и франшиз, построенная по модели SaaS (Software as a Service).

Проект полностью развернут в Production-режиме, работает на **вебхуках (Webhooks)** и изолирован внутри контейнеров Docker на сервере Aezza под управлением Nginx с автоматическим Wildcard SSL-шифрованием.

---

## 🔥 Что было реализовано в рамках технического рефакторинга:

### 1. Переход на монолитную архитектуру Webhooks (FastAPI + Aiogram 3)
* **Реактивный отклик:** Полностью ликвидирован опрос сервера (`polling`). Бот переведен на вебхуки. Telegram доставляет апдейты мгновенно через POST-запросы.
* **Слияние процессов:** Код Telegram-ботов и веб-страниц FastAPI объединен в единое сердце внутри одного Docker-контейнера `gym-api`. Управление сессиями и ботами встроено в современный жизненный цикл приложения (`lifespan`), что сэкономило оперативную память сервера.
* **Multi-Bot Dynamic Routing:** Платформа поддерживает одновременную работу бесконечного количества ботов. При старте система вытягивает активные токены из PostgreSQL, инициализирует их и генерирует для каждого уникальный защищенный URL-адрес вебхука вида `/webhook/bot/{token}`.

### 2. Инфраструктура Nginx & Wildcard SSL (Let's Encrypt / Certbot)
* **Динамические SaaS-поддомены:** Реализована классическая архитектура SaaS. Nginx и FastAPI перехватывают заголовок `Host`, парсят адрес и вытаскивают поддомен (например, `https://speedycrm.ru`). Бэкенд на лету понимает, данные какого именно клуба (`club_id = 123`) нужно отобразить.
* **Wildcard SSL:** Через Docker-контейнер Certbot выпущен единый сертификат Let's Encrypt со звёздочкой (`*.speedycrm.ru`), защищающий основной домен и абсолютно все ID-поддомены клиентов по протоколу HTTPS (порт 443).
* **Авто-редирект:** Все входящие незащищенные запросы с 80 порта (HTTP) принудительно перенаправляются на защищенный 443 порт (HTTPS).

### 3. Умная инлайновая авторизация и Слияние Аккаунтов
* **Сквозной Сценарий (User Flow):** Решена проблема рассинхронизации. Когда администратор на ресепшене вручную вносит атлета в базу и указывает телефон родителя, запись создается с `parent_id = None`.
* **Авто-вход:** При первом старте бота система проверяет Telegram ID, уходит в ветку отсутствия авторизации и выводит кастомную кнопку `request_contact=True`.
* **Слияние «на лету»:** Как только родитель нажимает *«📱 Войти по номеру телефона»*, бот очищает номер до 10 цифр, находит по индексу в PostgreSQL запись админа и жестко прописывает туда Telegram ID пользователя, открывая личный кабинет без повторного ввода данных.

### 4. Изоляция путей и SqlAdmin (Суперадминка)
* **Разделение прав:** Чтобы исключить конфликт роутов в FastAPI, веб-интерфейс администратора для Telegram WebApp освободил путь `/admin`.
* **Суперадмин-панель:** Полноценный интерфейс управления всей СУБД для главного разработчика (`sqladmin`) перенесен на секретный защищенный путь `/master-dashboard`, позволяя управлять франшизами и подписками в один клик. Кнопка быстрого перехода в SqlAdmin встроена прямо в закрытую клавиатуру суперадмина в Telegram.

### 5. Автоматизация SaaS-задач (APScheduler)
В фоне развернут асинхронный планировщик задач, который без участия разработчика выполняет критически важные бизнес-процессы:
* **Контроль прогульщиков (10 дней):** Ровно в 10:00 система сканирует поле `last_visit` и отправляет триггерные уведомления родителям, чьи дети пропустили 10 дней занятий при активном балансе абонемента.
* **Поздравление с Днем Рождения:** Автоматический утренний парсинг колонки дня рождения атлета (накатанной через миграции Alembic) с отправкой праздничных открыток.
* **Авто-бэкапы СУБД:** В 23:00 система делает полный слепок PostgreSQL, генерирует файл Excel через Pandas, отправляет его суперадмину в личку в Telegram через `BufferedInputFile` / `FSInputFile` и бесследно удаляет временный файл с диска сервера, соблюдая чистоту хранилища.
* **Вечерние бизнес-отчеты:** В 22:00 владельцы всех клубов (`owner_id`) получают персональную сводку по выручке, количеству отмеченных посещений за день и активным абонементам.

### 6. DevOps и CI/CD
* Проект полностью упакован в **Docker Compose** (PostgreSQL 15, Redis 7, Nginx Alpine, FastAPI, Certbot).
* Настроен `.dockerignore`, исключающий мусорные файлы и кэш из сборки образов.
* Развернут автоматический пайплайн **GitHub Actions** (воркфлоу тестов и проверок синтаксиса, собирающийся без ошибок при каждом пуше в ветку `master`).

## 🔒 Модуль биометрического прохода (Telegram WebApp СКУД)

Инновационная фича авторизации прохода спортсменов в клуб с помощью нативных технологий биометрии смартфона (**FaceID / TouchID**) через Telegram WebApp. Система полностью заменяет уязвимые QR-коды (которые можно скомпрометировать или переслать скриншотом) на полноценную сквозную цифровую подпись, привязанную к конкретному устройству родителя.

### 🚀 Архитектура и цепочка взаимодействия

1. **Telegram-Бот (Точка входа):**
   Родитель переходит в свой профиль. Бот генерирует клавиатуру с изолированной ссылкой на WebApp, привязанной к его SaaS-поддомену: `https://{club_id}.speedycrm.ru/webapp/biometric-pass`.
2. **Фронтенд (Telegram WebApp JS API):**
   * **Первый заход (Активация):** Скрипт через `Telegram.WebApp.BiometricManager` проверяет поддержку биометрии устройством. Если доступ не настроен, выводится интерфейс привязки. При сканировании лица/пальца отправляется запрос на бэкенд для активации флага `is_biometric_enabled = True` у пользователя.
   * **Последующие заходы (Запрос прохода):** При клике на карточку атлета всплывает системное окно авторизации FaceID смартфона. В случае успеха Telegram генерирует уникальный зашифрованный `biometric_token`.
3. **Бэкенд (FastAPI Security & Бизнес-логика):**
   * **Валидация сессии:** Метод `verify_telegram_data` выполняет криптографическую проверку строки `init_data` с помощью HMAC-SHA256 и токена бота (`bot_token` конкретного клуба). Это исключает возможность подмены `user_id` злоумышленниками.
   * **Защита от обхода:** Бэкенд строго сверяет наличие токена устройства в запросе, если в БД активировано поле `is_biometric_enabled`.
   * **Проверка лимитов:** Выполняется автоматический скоринг абонемента атлета (проверка на заморозку `is_frozen`, валидность даты окончания `expire_date` и наличие доступных уроков `balance_lessons`).
4. **Контроллер железа (СКУД):**
   При успешном прохождении всех фильтров FastAPI извлекает из JSONB-поля настроек клуба (`club_settings`) конфигурацию `dingtian_config` и отправляет асинхронный триггер в модуль `skud.py` для открытия физического реле турникета Dingtian. После этого на бэкенде списывается занятие, а WebApp обновляет баланс на экране.

### 💻 Развертывание и миграции в Production

Генерация и накат миграций осуществляются строго внутри изолированного Docker-контейнера бэкенда (`gym_crm_api`), чтобы обеспечить консистентность состояния базы данных `gym_db`:

```bash
# 1. Генерация автоматической ревизии Alembic
docker exec -it gym_crm_api alembic revision --autogenerate -m "add_biometric_to_user"

# 2. Применение изменений к СУБД PostgreSQL
docker exec -it gym_crm_api alembic upgrade head

# 3. Мягкий перезапуск сервиса для применения нового кода хендлеров
docker compose restart gym_crm_api
```
