# SpeedyCRM

SpeedyCRM — SaaS CRM для спортивных клубов на FastAPI, Aiogram 3, PostgreSQL, Redis и Docker.

## Возможности

- личный кабинет родителя и несколько атлетов в одном клубе;
- регистрация и авторизация пользователей;
- абонементы, занятия, безлимитные тарифы и заморозка;
- QR-пропуска и проход через FaceID/WebApp;
- интеграция с турникетом СКУД;
- история посещений и статистика клуба;
- онлайн-оплата через ЮKassa и ручная оплата по чеку;
- сохранение карты для оплаты в один клик;
- авторизация WebApp через подписанные Telegram `initData`;
- админ-панель, суперадмин и рассылки;
- камеры через go2rtc;
- фоновые задачи APScheduler;
- настраиваемый загрузочный экран WebApp с логотипом клуба;
- Docker Compose, Nginx, CI/CD и автоматические тесты.

Production-контейнер запускается от непривилегированного пользователя `appuser`. Исходный код не монтируется поверх образа; отдельно сохраняются только логи и загруженные логотипы.

## Структура проекта

- `main.py` — запуск FastAPI, Telegram-ботов и фоновых задач.
- `config.py` — загрузка переменных окружения.
- `admin_module/api.py` — FastAPI API, WebApp, аналитика и webhook ЮKassa.
- `handlers/` — Telegram-хендлеры, меню, регистрация, оплаты и админка.
- `services/` — бизнес-логика проходов, аналитика и клиент ЮKassa.
- `database/db.py` — SQLAlchemy-модели и операции с базой.
- `templates/` — HTML-страницы WebApp и админки.
- `static/` — CSS и статические файлы.
- `migrations/` — миграции Alembic.
- `tests/` — автоматические тесты.
- `go2rtc.yaml` — конфигурация видеопотоков.
- `docker-compose.yml` — сервисы приложения.

## QR, СКУД и посещения

Старый API-маршрут ручного открытия турникета `/open-turnstile` защищён заголовком `X-API-Key`. Пользователи его не вводят: пользовательский WebApp использует отдельный маршрут `/webapp/open-turnstile`, где сервер проверяет подписанные Telegram `initData`, принадлежность атлета родителю и клубу.

Админская WebApp-панель `/admin` также сначала проверяет Telegram `initData` и доступна только владельцу клуба или суперадминистратору. API-ключ для открытия админки не требуется.

QR-код имеет формат:

```text
student:<student_id>:<time_salt>:<signature>
```

Подпись проверяется через HMAC. Поддельный или повреждённый QR не передаётся в сервис прохода.

Проход дополнительно проверяет:

- существование атлета;
- принадлежность атлета текущему клубу;
- срок действия абонемента;
- наличие занятий или безлимит;
- повторный проход в активной сессии;
- защиту от быстрых повторных запросов.

`Student.last_visit` используется как маркер активной сессии. После завершения сессии фоновая задача закрывает её и списывает одно занятие. Таблица `visit_logs` хранит отдельную историю всех успешных проходов.

## Оплаты

Разовые платежи создаются через ЮKassa. После события `payment.succeeded` webhook:

1. находит заказ по `metadata.order_id`;
2. помечает заказ как `CONFIRMED`;
3. при первой оплате сохраняет идентификатор карты для повторных списаний;
4. начисляет выбранный тариф атлету;
5. отправляет уведомление родителю.

Оплата сохранённой картой выполняется в один клик. Параметры тарифа сохраняются в `PaymentOrder`.

### Платная заморозка абонемента

В профиле клиента доступна отдельная кнопка `❄️ Купить заморозку`, если администратор клуба указал цену одного дня.

Сценарий покупки:

1. клиент выбирает атлета с действующим и ещё не замороженным абонементом;
2. вводит необходимое количество дней — от 1 до 365;
3. система рассчитывает сумму по формуле `количество дней × цена одного дня`;
4. после успешной оплаты сразу продлевает `Student.expire_date` на выбранное число дней;
5. атлет сразу переводится в состояние заморозки (`is_frozen = 1`), а оплаченные дни начинают действовать немедленно;
6. при первом проходе через СКУД заморозка снимается, но добавленные дни остаются в дате окончания абонемента.

Немедленный перевод в заморозку является намеренным поведением: клиент покупает услугу, чтобы начать заморозку сейчас. Если нужно только купить запас дней без немедленного запуска, это должен быть отдельный сценарий — например, баланс или сертификат заморозки.

Платная заморозка не расходует бесплатное право `Student.can_freeze`, но не может быть применена к просроченному или уже замороженному абонементу. Повторная обработка одного платежа защищена статусом `PaymentOrder` и блокировкой заказа.

Поддерживаются:

- онлайн-оплата новой картой через ЮKassa;
- оплата сохранённой картой;
- перевод по СБП с подтверждением чека администратором.

Типы заказов платной заморозки имеют префикс `FREEZE` (`FREEZE_FIRST`, `FREEZE_RECURRING`). Они обрабатываются отдельно от покупки абонемента, поэтому заморозка не начисляет занятия и не становится шаблоном для будущего автопродления.

Автопродление через `saas_recurrent_payments_job` умеет восстанавливать количество занятий, срок и дисциплину из последнего подтверждённого заказа. Сам запуск cron-задачи сейчас оставлен отключённым в `main.py` и включается отдельно после проверки боевого сценария ЮKassa.

## Камеры

- в `templates/cameras.html` доступно переключение между четырьмя камерами;
- API получает источник через `camera_src`;
- поток проксируется через go2rtc;
- MJPEG boundary и ошибки upstream корректно передаются клиенту.

## Загрузочный экран WebApp и логотип

В Telegram-админке откройте `Настройки` и используйте кнопки:

- `🎨 Загрузочный экран WebApp` — включение и базовые параметры;
- `🖼 Загрузить логотип WebApp` — отправьте изображение боту как фото.

Логотип сохраняется локально в `static/uploads/logos/`, а ссылка автоматически записывается в настройки клуба. Вручную задавать внешний URL не требуется.

Для логотипа действует ограничение 5 МБ. При сохранении файл проверяется как изображение, приводится к JPEG и уменьшается максимум до 2000×2000 пикселей.

Параметры загрузочного экрана хранятся в `clubs.club_settings`:

```json
{
  "ui": {
    "club_name": "Название клуба",
    "logo_url": "/static/uploads/logos/club_1_logo.jpg",
    "loading": {
      "enabled": true,
      "duration_ms": 1200,
      "message": "Загружаем приложение…"
    }
  }
}
```

`duration_ms` ограничен диапазоном от 300 до 10000 миллисекунд. Название клуба берётся из записи клуба, если в старых настройках осталось значение `Новый фитнес-клуб`.

В интерфейсе безлимитные тарифы отображаются как `♾ Безлимит`; технический маркер `999` используется только внутри базы данных и не показывается пользователю.

## Конфигурация

Секреты и подключения задаются через `.env`. Файл не должен попадать в Git.

Основные переменные:

```env
BOT_TOKEN=...
DATABASE_URL=postgresql+asyncpg://...
DB_PASSWORD=...
ADMIN_IDS=...
SECRET_KEY=...
API_STATS_KEY=...
```

Настройки конкретного клуба — в поле `clubs.club_settings`: направления, тарифы, лимиты, ЮKassa, турникет и камеры.

Ключи ЮKassa задаются администратором конкретного клуба через FSM-админку и хранятся в JSONB-настройках клуба:

```json
{
  "payments": {
    "yookassa_shop_id": "...",
    "yookassa_secret_key": "..."
  }
}
```

При обработке webhook система выбирает ключи по `order.club_id`, поэтому разные SaaS-клубы используют свои магазины ЮKassa.

Webhook ЮKassa не требует ручного API-ключа от пользователя. Сервер получает `payment.id` из уведомления и проверяет платёж через официальный API ЮKassa по ключам конкретного клуба, затем сверяет статус, валюту, сумму и `metadata.order_id` с заказом.

Цена платной заморозки задаётся в Telegram-панели администратора: `Настройки клуба` → `Управление лимитами` → `Цена 1 дня заморозки`.

В конфигурации это поле хранится так:

```json
{
  "limits": {
    "freeze_price_per_day": 150
  }
}
```

Значение `0` отключает кнопку покупки для клиентов. Цена задаётся в рублях и может быть дробной. Общая настройка `features.freeze` также должна быть включена.

## Проверка перед использованием клуба

Запуск тестов:

```bash
python -m pytest -q
```

Текущий набор покрывает 19 тестов:

- HMAC и Telegram WebApp;
- QR-проверки и отказ поддельного QR;
- изоляцию клубов;
- проходы, баланс, срок действия и антиспам;
- камеры и проксирование go2rtc;
- формирование платежей ЮKassa и автосписание.

Перед регистрацией реальных людей рекомендуется проверить:

1. регистрацию родителя и атлета;
2. создание QR и проход через турникет;
3. списание занятия после завершения сессии;
4. тестовый платёж ЮKassa;
5. получение webhook и начисление абонемента;
6. уведомление родителя;
7. резервное копирование базы.

## Запуск

Локально:

```bash
python main.py
```

Через Docker Compose:

```bash
docker compose up -d --build
```

Просмотр логов:

```bash
docker compose logs -f
```

## Важные замечания

- Не удаляйте `.env` с рабочего сервера без резервной копии настроек.
- Не включайте автосписания, пока не проверены тестовая карта, webhook и повторное начисление тарифа.
- Не меняйте схему базы вручную — используйте Alembic.
- Перед обновлением приложения рекомендуется сделать backup базы.
