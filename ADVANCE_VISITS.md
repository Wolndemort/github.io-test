# Авансовые посещения: правила учёта

Актуально на 30.10.2026. Документ описывает действующую логику на `master`.

## Числовые лимиты

Настройки клуба задают два независимых ограничения:

- максимум дней долга: **15 дней** по умолчанию;
- максимум долговых посещений: **7 посещений** по умолчанию.

Для production-клуба `id=2` на момент обновления документа установлено: `enabled=true`, `max_debt_days=15`, `max_debt_lessons=7`.

Числа `2 посещения` и `4 дня`, которые приводились в переписке, были только примером. Фактические числа всегда рассчитываются отдельно для каждого атлета и берутся из `advance_debt_lessons` и `advance_debt_days`.

## Как начисляется долг

1. Долг появляется только после окончания абонемента и только при новом входе/новой сессии.
2. Повторный вход внутри активной сессии не создаёт новое долговое посещение.
3. Каждое новое долговое посещение увеличивает `advance_debt_lessons` на 1.
4. `advance_debt_days` — период фактического долга: от первого долгового входа до последнего фактического долгового входа включительно. Простои после окончания абонемента, когда атлет не приходил, в долг не попадают.
5. Посещение не записывается, если следующий проход превысит хотя бы один лимит.
6. Для ручной отметки сотрудником после окончания абонемента требуется явное подтверждение предупреждения.

## Как погашается долг

Погашение выполняется внутри транзакции покупки абонемента с блокировкой атлета, поэтому два одновременных webhook/кассовых действия не должны списать долг дважды.

- Тариф с ограниченным количеством занятий: списывается минимум между долгом и количеством занятий в новом тарифе; срок нового тарифа также уменьшается на накопленные дни фактического долга.
- Безлимит (`count=999`): долговые занятия закрываются полностью, а срок нового тарифа уменьшается на дни долга.
- Если нового тарифа недостаточно, остаток долга сохраняется и показывается снова.
- Если функция авансовых посещений позже выключена, уже существующий долг всё равно погашается при покупке; выключенный флаг запрещает только создание новых долговых посещений.
- Заморозка абонемента долг не погашает.

Формулы:

```text
days_consumed = min(debt_days, new_subscription_days)
lessons_consumed = debt_lessons                    # безлимит
lessons_consumed = min(debt_lessons, new_tariff_lessons)  # обычный тариф
credited_days = new_subscription_days - days_consumed
credited_lessons = new_tariff_lessons - lessons_consumed
```

Все значения неотрицательные. Маркер `999` — это безлимит, а не 999 реальных занятий.

## Что видит клиент и администрация

При нулевом долге отображается обычный баланс абонемента. При ненулевом долге строка баланса заменяется предупреждением с текущим количеством долговых посещений и расчётом для тарифа по занятиям/безлимита. После погашения автоматически возвращается обычный баланс.

Каждое утро в 08:30 по Москве владелец, менеджеры и кассиры получают предупреждение со списком должников, датой окончания абонемента, количеством долговых посещений и возрастом долга. Тренеры эту рассылку не получают.

## Источник истины

Факт прохода хранится в `VisitLog`; долговые входы маркируются `source="advance"`, а поля долга на `Student` хранят накопленный расчёт до последнего фактического визита. Кэш `Student.last_visit` используется только для определения активной сессии и не заменяет историю посещений. Старые долговые записи без этой маркировки не пересчитываются задним числом.
